# Cosmopedia Small LM

A small GPT-style (decoder-only Transformer) language model built **from scratch**
in PyTorch and pretrained on the
[`HuggingFaceTB/cosmopedia`](https://huggingface.co/datasets/HuggingFaceTB/cosmopedia)
dataset (`auto_math_text` subset).

This is a learning / educational project: the goal is to implement every stage of
a language-model pipeline by hand — data cleaning, tokenizer training, the
Transformer itself, the training loop, sampling, evaluation, and deployment —
rather than to produce a state-of-the-art model.

> ⚠️ This is a ~10.7M-parameter base model trained on a small corpus. It performs
> next-token continuation of a prompt. It is **not** instruction-tuned and does
> **not** chat; expect simple, sometimes incoherent text.

---

## Model at a glance

| Property            | Value                                   |
| ------------------- | --------------------------------------- |
| Architecture        | Decoder-only Transformer (GPT-style)    |
| Parameters          | ~10.7M (10,745,856)                     |
| Vocabulary size     | 9,000 (byte-level BPE)                  |
| Context length      | 256 tokens                              |
| Embedding dim       | 384                                     |
| Layers              | 6                                       |
| Attention heads     | 6 (head dim 64)                         |
| Feed-forward mult.  | 4× (384 → 1536 → 384)                   |
| Weight tying        | Yes (input embedding = output head)     |
| Objective           | Next-token prediction (causal LM)       |

All architecture values live in [`configs/run_01.yaml`](configs/run_01.yaml) and are
read into `ModelConfig` at load time.

## Project structure

```
configs/        run_01.yaml — architecture + training hyperparameters for one run
src/            reusable building blocks (one class per stage)
  ├─ model.py            the Transformer (OwnLLM)
  ├─ attention.py        causal self-attention
  ├─ mlp.py              feed-forward network
  ├─ transformer_block.py
  ├─ model_config.py     ModelConfig + load_config()
  ├─ train_config.py     TrainConfig
  ├─ tokenizer.py        byte-level BPE tokenizer (HF tokenizers)
  ├─ dataset_builder.py  encode docs -> train.bin / val.bin
  ├─ data_cleaner.py     stage 2: cleaning
  ├─ data_filter.py      stage 3: filtering + PII masking
  ├─ deduplicator.py     stage 4: deduplication
  ├─ trainer.py          the training loop
  ├─ lr_scheduler.py     warmup + cosine decay
  ├─ checkpoint.py       save/load checkpoints
  └─ jsonl_io.py         read/write JSONL
inference/      serving engine
  ├─ engine.py           load once, generate many times
  └─ sampling.py         temperature / top-k / top-p / repetition penalty
evaluation/     evaluate.py, generate.py, perplexity.py
deployment/     app.py (FastAPI) + Dockerfile
tokenizer/      trained tokenizer.json
checkpoints/    model.pt (inference-only weights)
```

## The pipeline

The model is produced in stages. Each stage reads the previous stage's output.
Run the scripts in `scripts/` in order (adjust the script names to match yours):

```bash
# 1. Download the dataset  (HuggingFaceTB/cosmopedia, auto_math_text) -> data/raw/
# 2. Clean      -> data/cleaned/
# 3. Filter + mask PII  -> data/filtered/
# 4. Deduplicate  -> data/final/
# 5. Train the tokenizer  -> tokenizer/tokenizer.json
# 6. Build the dataset  -> dataset/train.bin, dataset/val.bin, dataset/meta.json
```

Then train:

```bash
python scripts/train.py --config configs/run_01.yaml
```

Training uses AdamW (weight decay 0.1, applied only to 2-D weight matrices),
a linear warmup + cosine learning-rate schedule (peak LR 3e-4), gradient
accumulation, gradient clipping, and automatic mixed precision on CUDA.

## Generate text

Compare how `temperature` changes the output, using the real sampling pipeline:

```bash
python evaluation/generate.py --prompt "Scatterplots are graphs used to visualize the"
python evaluation/generate.py --prompt "Once upon a time" --temperatures 0.2 0.8 1.5
```

Lower temperature → safer, more repetitive; higher → more varied, less coherent.

## Serve the model (FastAPI)

Run the API locally:

```bash
uvicorn deployment.app:app --reload --port 8000
```

Then open `http://localhost:8000/docs` for an interactive tester, or call it directly:

```bash
curl -X POST http://localhost:8000/generate \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Once upon a time", "max_tokens": 50, "temperature": 0.8}'
```

Endpoints:

| Method | Path        | Purpose                          |
| ------ | ----------- | -------------------------------- |
| POST   | `/generate` | generate a continuation          |
| GET    | `/health`   | liveness / which device is used  |

### Docker

```bash
docker build -t cosmopedia-small-lm .
docker run -p 8000:8000 cosmopedia-small-lm
```

The image installs the **CPU** build of PyTorch and serves
`checkpoints/model.pt` (inference-only weights, optimizer state stripped out).

## Limitations

- **Tiny model, small corpus.** ~10.7M parameters; it learns basic structure of
  the text, not facts or reasoning.
- **Base pretraining only.** No instruction tuning / RLHF — it continues a prompt,
  it does not follow instructions or hold a conversation.
- **Can produce incoherent text,** especially at high temperature.
- **Domain-limited** to the style of the `auto_math_text` Cosmopedia subset.
